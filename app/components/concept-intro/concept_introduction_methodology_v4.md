# Concept Introduction Sections — Methodology

## Scope

Covers the section on a content page where a concept is introduced for the first time.
Usually that is the page's first section, but not always: read the content and pick the section
where the concept is actually introduced. It is never the page intro (the text above the sections).
Does not cover definitions pages, which stay canonical and encyclopedic.

Division of labour:

- **Definitions page** — formal statement, conditions, related terms. Archival.
- **Content page introduction** — comprehension. Less systematic, aimed at intuitive grasp.

The content page must not repeat the definitions page. The formal statement appears here as
compression of something already shown, not as the opening move.

## Selection

Not every section gets this treatment. Applying it uniformly destroys the signal.

- One concept per page as a rule: the one the page is dedicated to, usually named in the slug.
- A section that merely states a property, a cost, or a consequence stays plain prose.
- Of the sections that get a template, few get an analogy.
- Visuals are not rationed the same way. Inside a section that gets a template, every beat
  carrying something the reader has not yet been shown is illustrated — see *Visuals*.

## Elements

### Obligatory

| Element | Content |
|---|---|
| **Intuition** | Why the thing exists. The problem that forces it, in vocabulary the reader already has. |
| **Definition** | Answers *what is this?*, in the form *this is that*. Carries notation and conditions inside it. Nothing else — see *The definition block* below. |
| **What kind of thing it is** | Number, function, operation, property, set. Prevents category errors nothing later will fix. Its own beat, never inside the definition block. |
| **Example** | One instance, concrete enough to check by hand. |
| **Second register** | The same concept shown a second way — see *Registers* below. One description is a claim; two that agree are understanding. |
| **Caveat** | Where it fails, what it costs, what it does not cover. A concept with no edges has no shape. |
| **Exit line** | What the rest of the page will do. Without it the reader does not know they are finished. |

### Optional

| Element | Trigger |
|---|---|
| **Analogy** | Only if an honest one exists. Lives inside the intuition as ordinary prose — never a labelled block. Must state where it breaks, or it teaches something false. |
| **Visual** | When the concept is spatial, when a trend matters more than any single value, or when a comparison is easier seen than read. |
| **Takeaway phrase** | One compressed line, only if it comes naturally. Forcing it produces slogans. |

### Rules

- The definition never appears in the first paragraph.
- Something pointable always precedes the name.
- The section ends pointing forward, not concluding.
- No concept is carried by a single register. At least two, and they must be visibly the same
  concept, not two topics side by side.
- Every template names one **carrier step**, marked *Carrier* in the ordering below. That step
  delivers the second register and it is not prose — numbers worked, a picture drawn, a table
  laid out, objects listed. If the concept admits no honest non-verbal showing at that step, the
  template is the wrong one for the concept. Choose another rather than writing the step in words.

## The definition block

The block holds a definition and nothing else. A definition answers one question — *what is
this?* — and answers it in the form *this is that*: the term on the left, the category and the
condition that narrows it on the right.

What does not go in it:

- The argument that produced the definition. That is the beat before.
- An account of how the thing came about, or why someone would want it. That is the intuition.
- Discussion, consequences, what to watch out for. Those are later beats.
- **What kind of thing it is.** It is a separate obligatory element and it is not a definition.
  It follows the block as its own beat, in plain prose.

A block that reads as a short essay is the common failure, and it is easy to miss because the
prose is often good. The test is blunt: strike every sentence that is not of the form *this is
that*. What remains is the definition. If nothing remains, the block never had one.

**Length is whatever answering the question takes.** It is short here for a reason that is not
style: the definitions page carries the formal, extended statement, and a content page that
reproduces it has duplicated the archive instead of introducing the concept.

**The term links to its definitions-page entry**, contextually, on first mention inside the
block.

## Templates

Nine orderings. The elements are the same; only the sequence changes.

### Choosing

| Concept is… | Template |
|---|---|
| buildable by hand on small numbers | A · definition last |
| dependent on vocabulary that must exist first | B · definition first |
| a precondition — meaningless until something breaks | C · failure first |
| a rival to a method that already works | D · comparison |
| an extension of something known | E · widening |
| the same object under two unrelated descriptions | F · collapse |
| defined by its boundary | G · exclusion |
| the answer to a question current tools cannot reach | H · open question |
| already in use informally, unnamed | I · naming |

---

### A · Definition last

1. **Intuition** — what is annoying, in words they already have. *Analogy here.*
2. **Example** — do it on small numbers. *Visual here. Carrier: the arithmetic, worked on the
   page, not described.*
3. **Forcing** — nothing was chosen; each step was pinned by the one before
4. **Definition** — name, notation, conditions
5. **What kind of thing it is**
6. **Caveat** — what generalizes, what was peculiar to those numbers, where it is fragile
7. **Exit line**

*They build it, then find out what it is called. Step 3 is the hinge — without it the example is
an illustration rather than a derivation.*

### B · Definition first

1. **Intuition** — the difficulty without it. *Analogy here.*
2. **Definition** — *Visual here. B is the one template whose definition takes one: nothing has
   been shown yet, so this is also what puts something pointable before the name.*
3. **What kind of thing it is**
4. **Example** — the same statement on numbers. *Visual here. Carrier: the numbers. A paragraph
   restating the definition in easier words is the failure this step exists to prevent.*
5. **Verification** — check the definition kept its promises
6. **Caveat** — scope
7. **Exit line**

*The ordinary order. Step 5 is what saves it from being a textbook: the definition made claims,
and they get tested rather than illustrated.*

### C · Failure first

1. **Intuition** — the assumption a sensible reader would make, stated fairly
2. **Example** — run it, let it break. *Visual here. Carrier: the break itself — the values, the
   graph, or the step where it fails. The reader watches it happen.*
3. **Diagnosis** — the break was predictable; show the sign readable beforehand. *Analogy here.*
4. **Definition** — the condition that prevents it, stated as an equivalence
5. **What kind of thing it is**
6. **Caveat** — read the equivalence backwards: the failure is now a test
7. **Exit line**

*The concept is a precondition, so it means nothing until something dies without it.
Step 3 separates this from a bare counterexample.*

### D · Comparison

1. **Intuition** — the old method works; the new one owes an explanation
2. **Example** — what the old one wastes. *Visual here — the waste must be pointable. Analogy here.
   Carrier: that visual. It is not optional in this template — the waste is the argument, and an
   argument the reader cannot point at is a claim.*
3. **Definition** — the replacement
4. **What kind of thing it is**
5. **Free consequences** — what follows unasked
6. **Caveat** — the single cause behind all of it, and what that cause costs
7. **Exit line**

*Nothing is broken, so the argument is about waste. Step 6 is mandatory — without it this
degenerates into a feature list.*

### E · Widening

1. **Intuition** — what you can already do
2. **Example** — the one thing you cannot. *Visual here — the wall. Carrier: the wall, drawn or
   computed up to the point it stops. Stated rather than shown, it is an assertion the reader
   takes on trust.*
3. **Definition** — admit one new object, nothing more. *Analogy here.*
4. **What kind of thing it is**
5. **What survives** — the old rules still hold
6. **Caveat** — what you lose
7. **Exit line**

*The reader must be persuaded the addition is minimal and safe. Step 5 persuades; step 6 keeps
it honest.*

### F · Collapse

1. **Intuition** — the first account. *Visual here — usually the picture side.*
2. **The second account** — a wholly different description
3. **Example** — same case, both ways, same answer. *Table or side-by-side. Carrier: steps 1 and 2
   are already two registers by construction — this is where they are made to meet, on one case,
   with the answers matching in view.*
4. **Why they had to agree** — the two were never separate
5. **Definition** — the thing both describe
6. **Caveat** — which account to reach for when
7. **Exit line**

*Students learn the two faces as unrelated. Step 4 is the whole point. No analogy — the two
accounts already illuminate each other.*

### G · Exclusion

1. **Intuition** — several plausible candidates; ask which fails. *Visual here — all at once.
   Carrier: the candidates as objects, drawn or listed in their own terms. Characterised in prose
   they all sound alike, which is the misconception rather than the cure.*
2. **Sort them** — reveal which
3. **The fault** — where exactly it fails, and why the near-misses do not
4. **The rule** — what separates them. *Analogy here.*
5. **Definition** — the name
6. **What kind of thing it is**
7. **Caveat** — the rejected candidate is usually salvageable
8. **Exit line**

*Defined by its boundary, so the boundary comes first. Step 3 must also explain the passes —
that is where the real misconception lives.*

### H · Open question

1. **Intuition** — a question anyone can ask
2. **Dead end** — the usual tools give nothing. *Visual here.*
3. **Approach** — get close instead of arriving. *Table here — the trend is the argument. Analogy
   here. Carrier: that table. The reader must see the values move, not read that they do.*
4. **Definition** — name the move
5. **What kind of thing it is**
6. **Caveat** — persuasive, not yet proven
7. **Exit line**

*The question must be felt as unanswerable first. Step 6 matters — admitting the table is not a
proof is what points to the next section.*

### I · Naming

1. **Intuition** — you already do this
2. **Example** — two or three other places it happens. *Visual here — side by side. Carrier: the
   instances themselves, each shown in its own terms. Summarised in prose they lose the surface
   differences, and the recognition in step 3 has nothing to work against.*
3. **What they share** — the common structure
4. **Definition** — the name and precise conditions
5. **What kind of thing it is**
6. **Caveat** — what the name buys: prove once, use everywhere
7. **Exit line**

*Nothing new is introduced, only recognised. No analogy — the template is analogy throughout.
Step 6 answers the question the reader actually has: why bother naming it.*

## Registers

A register is a way of describing a concept. The same concept looks different in each, and a
reader who has seen it in only one has learned a notation rather than an idea.

| Register | Shows |
|---|---|
| **Verbal** | What the thing is for, in ordinary words. The problem that forces it. |
| **Algebraic** | The concept as symbols and computation — worked on real numbers, small enough to check by hand. |
| **Geometric / spatial** | The concept as a picture, a movement, a region, a position. |
| **Numeric / tabular** | Values laid out so a pattern, a trend, or a boundary becomes visible. |
| **Structural** | What the object relates to: arrows, trees, containment, ordering, mappings. |
| **Procedural** | The concept as a sequence of steps that produce it. |
| **Counterexample** | The concept by its edge — the nearest thing that is not it, and why. |

### The rule

Every concept introduction carries **at least two registers**, and they must be recognisably the
same concept: the same object, the same numbers, the same example, seen twice. Two registers that
do not meet are two half-explanations.

Prose is a register but never counts as the second one. A section made of words plus more words
has one register regardless of length.

The second register is not an extra block to write. It is carried by a step the template already
has — the one marked *Carrier*. Finding that step written in prose is the single most common way
a section that passes every other check still teaches nothing.

### Choosing the second

Take the register the concept is *not* usually taught in. The reader arrives holding the standard
one; the second is what they came for.

| The concept usually arrives as | Reach for |
|---|---|
| a formula | the picture, or the worked number |
| a shape | the algebra that produces it |
| a rule or procedure | the case where it fails |
| a definition | a table of instances that satisfy and violate it |
| a count | the objects being counted, drawn or listed |

### Making them meet

Registers only teach together when they are visibly locked to each other. The mechanisms:

- **One running instance.** The same matrix, the same triangle, the same function, the same
  number, carried through every register in the section. Switching examples between registers
  breaks the link and the reader learns two unrelated things.
- **Shared labels.** If the picture says $\sigma_1$, the algebra says $\sigma_1$, and the table
  column says $\sigma_1$.
- **A stated correspondence.** One sentence saying what in register A is what in register B —
  *the semi-axis lengths of the ellipse are the numbers on the diagonal*. Without it the reader
  is left to guess, and usually does not.
- **An arithmetic check.** Where a quantity can be confirmed two ways, confirm it:
  $\sigma_1\sigma_2 = |\det A|$. The check is what turns two descriptions into one fact.

### Per section

The registers available differ by subject; the requirement does not.

| Section | Typical pairing |
|---|---|
| Linear algebra | algebraic ↔ geometric — the computation and what it does to space |
| Calculus | algebraic ↔ graphical — the limit or derivative and the curve it describes |
| Probability | numeric ↔ structural — the count or the value, and the sample space it comes from |
| Combinatorics | algebraic ↔ enumerative — the formula and the objects listed out |
| Geometry | spatial ↔ algebraic — the construction and the coordinates or the measure |
| Trigonometry | geometric ↔ algebraic — the circle or triangle and the identity |
| Functions | graphical ↔ tabular ↔ algebraic — shape, values, rule |
| Set theory · Logic | structural ↔ verbal — diagram or truth table, and the statement |
| Arithmetic · Algebra | numeric ↔ symbolic — the worked case and the general rule |
| Complex numbers | algebraic ↔ geometric — the operation and the plane |

## Visuals

A visual is how a non-verbal register is delivered. Choosing one means first choosing the register
it serves, then the form that carries it.

### Where they go

**Every beat that carries something the reader has not yet been shown is illustrated.** Any form
will do — a graph, a table, a drawing, a scheme, a diagram. The rule is about the beat's content,
not its position in the ordering: a beat introduces something, so it shows it.

**The opening beat above all.** It is the one most often left as bare prose and the one that can
least afford to be. The ideas it reaches for are frequently remote from the concept itself —
undoing an addition, a method that already works, a question anyone can ask — and in words alone
the reader may not see what is being got at until several beats later, if at all. A reader who
opens a section onto an unbroken wall of text also has no particular reason to begin. A picture
supplies both the reason and the thing the later beats will push against.

**The definition is the usual exception.** By the time it arrives, everything in it has already
been shown, and its job is compression; a picture there repeats what the reader just saw.

**Template B is the exception to the exception.** There the definition is step 2 and the example
does not arrive until step 4, so the definition genuinely carries something unshown and takes an
illustration. This is also what rescues B from the rule that something pointable must precede the
name: in B the picture at the definition is that pointable thing.

**The carrier step is a separate requirement and is not discharged by this one.** Its job is to
deliver the second register. The visuals here serve comprehension beat by beat. A section can be
fully illustrated and still fail the carrier rule if the carrier step was written in words.

### Where to find them

1. Look first in the visual tools: the section's own `/<section>/visual-tools/` pages
   (`pages/<section>/visual-tools/`) and the global `/visual-tools/` section (`pages/visual-tools/`,
   the older structure).
2. If a tool's frozen state shows what the step needs, use it, and plant a link from the step to
   that tool.
3. Only if no frozen state fits, make something new.

Each introduction is done one at a time and reviewed by the owner before the next.

### Kinds

Kinds: illustration · table · graph · annotated formula · before/after pair · step strip ·
arrow mapping · number line · tree · region diagram · colour-coded expression ·
interactive tool.

Choose by what is being shown, not by topic:

- spatial → illustration
- trend → table or graph
- comparison → side by side
- structure → arrows or tree
- a quantity that changes with an input → interactive tool

Every visual carries the running instance of the section — the same numbers that appear in the
prose and the algebra. A diagram drawn from a different example is a second topic.

Every visual states its correspondence, in the caption or the sentence beneath it: what element of
the picture is what quantity in the text. A picture that has to be decoded teaches decoding.

### Tables

A table is the numeric or structural register, not decoration. It earns its place when the reader
needs to compare rows against the same columns, or see a pattern across values that prose would
have to list.

- Every column is a question asked of every row. A column that applies to one row is a footnote.
- The rows carry the running instance where possible — the same objects the section is about.
- The prose does not restate the cells. It says what the table shows that the cells do not.

### Interactive tools

Tools live in `/section/visual-tools/` and are the register where a relationship only becomes
visible under variation — where the reader must move something to see what holds and what changes.

- A tool is warranted when a static picture would need three or more frames to make the point.
- It carries presets, and the presets are the section's cases: the ordinary one, the one where
  the requirement fails, the degenerate one.
- It shows the algebra alongside the picture — the numbers updating as the reader drags is the
  correspondence, made continuous.
- The section links to the tool at the point the variation matters, not as an appendix.

| Component | File |
|---|---|
| `DiagramsFrame`, `DiagramsFrameV2` | `app/components/infographics/` |
| `IdentitySheet`, `ObjectTypeProfile`, `PropertyLawCard` | `app/components/infographics/linear-algebra/` |
| `CalloutBlockGroup` | `app/components/page-components/new-layout/` |

sign the wrong layer is being used.

## Formulas

Canonical formulas use the existing pipeline. Do not hand-write `$$...$$` for anything in the
formulas repository.

- The callout sits **inside the definition element**, immediately after the plain-language
  sentence.
- `formulas_link` follows the callout.
- Never before the definition sentence — a formula arriving before the reader knows what it
  computes is the failure being corrected.

```
@academic[formula_callout:key|Display Name|$$ ... $$]@
@academic[formulas_link:/section/formulas#key]@
```

Inline `$...$` in prose stays as is — worked numbers, checks, small algebra. Those are not
canonical formulas.

## Links

Three destinations, one job each:

| Destination | Attached to |
|---|---|
| definitions page | the term itself, on first mention |
| formulas page | under the formula callout, via `formulas_link` |
| related content page | the concept the argument depends on, at the point it is needed |

One link per element. Verify definitions anchors against the live page before shipping.

The anchor is the entry's `id` from `app/api/db/definitions/<section>/<section>Definitions.js` —
a word id such as `#piecewise_function`, never a number. Where an entry has no `id` (all of
algebra and set theory), the anchor is the name, lower-cased, spaces turned into `_`. A name with
brackets or an apostrophe then gives an anchor like `#null_space_(kernel)`, so check it on the
page rather than guessing.

Existing conventions apply unchanged: in-text markdown links use `!/path`, structured `link:`
objects use plain `/path`, links and bold are mutually exclusive.

## Structure and marking

Flat prose. No rails, no numbered beats, no boxed scheme headers.

Seams are carried by the opening clause of each beat, bolded, stating what that beat does.
Scanning only the bolded openings should give the whole argument.

**The clause sits on its own line.** The beat's text begins on the line below it, after a gap —
never running on from the clause as part of the same line.

**So the clause has to be a complete sentence**, able to stand alone. A clause that continues
grammatically into what follows — *Each of the six functions needs its own band,* then *chosen
the same way…* — reads as a broken line once it is lifted onto a line of its own. Write it to
end where the line ends.

Three visual weights, used consistently:

| Weight | Means |
|---|---|
| tinted grey ground | the worked instance |
| tinted blue card | the definition |
| plain prose | everything else |

**Three, not four.** A beat where something fails is still a worked instance and still sits on
the grey ground; the failure is marked with a red accent on top of it — a rule, a marker, a
coloured value — never a ground of its own. A second kind of instance box would make the reader
learn the difference between two tints before reading anything.

The analogy gets no box. If boxed it competes with the definition, and a section with no analogy
then looks incomplete.

## Writing it with `ConceptIntro`

The section is rendered by `ConceptIntro.jsx` in this folder: `<ConceptIntro data={{ beats }} />`.
Each step of the template is one item in `beats`, in template order. The component does not know
which template is used; the order of the array is the template.

| Step | `kind` | Shows as |
|---|---|---|
| Example, worked case | `'instance'` | grey ground |
| Definition | `'definition'` | blue card |
| Every other step, including *what kind of thing it is* | `'prose'` (the default) | plain prose |

A step where something fails adds `tone: 'break'` — red accent and left rule, same ground.

Fields for every kind:

| Field | Holds |
|---|---|
| `lead` | the bolded opening sentence |
| `content` | the step's text |
| `visual` | a component, never raw SVG markup written in the page file |
| `caption` | the correspondence: what in the picture is what in the text |
| `note` | a closing line under the whole step, when a table and a figure share one correspondence |

Fields for `kind: 'definition'` only:

| Field | Holds |
|---|---|
| `kicker` | the small heading; defaults to *The definition* |
| `statement` | the *this is that* sentence, with the term linked to its definitions entry |
| `formula` | the `@academic[formula_callout:…]@` string |
| `footer` | the `@academic[formulas_link:…]@` string, or a related-page link |

There are no `gloss` or `kindOfThing` fields. The component warns in development if they are
passed; that text goes in its own `'prose'` step after the card.

All text fields go through `processContent`, so they take only its syntax: `$math$`, `**bold**`,
`[label](!/path)`, `@[code]@`, `@academic[…]@`.

An older component with the same name, `app/components/page-components/content-components/ConceptIntro.jsx`,
takes a different shape (`data.blocks` with `type`, and `gloss` / `kindOfThing` inside the
definition). This doc does not apply to it.

## Checklist before shipping

- [ ] Definition is not in the first paragraph
- [ ] Something pointable appears before the name
- [ ] The definition block answers *what is this?* and holds nothing but the answer
- [ ] The term in the definition links to its definitions-page entry
- [ ] The kind of thing it is, stated — as its own beat, outside the definition block
- [ ] Caveat present — the concept has edges
- [ ] Exit line points at the next section
- [ ] If analogy present, it says where it breaks
- [ ] At least two registers present, and neither of them is prose alone
- [ ] The carrier step is non-verbal — worked numbers, a picture, a table, or objects listed
- [ ] The registers carry the same running instance — same numbers, same object
- [ ] The correspondence between registers is stated, not implied
- [ ] Where a quantity can be checked two ways, it is checked
- [ ] Every beat carrying something unshown has an illustration
- [ ] The opening beat has one
- [ ] The definition has none — unless the template is B
- [ ] A failure beat sits on the grey ground with a red accent, not a ground of its own
- [ ] Every table column is a question asked of every row
- [ ] Canonical formulas use callouts, not raw display math
- [ ] Definitions anchor verified against the live page
- [ ] Each bolded opening is a complete sentence on a line of its own
- [ ] Bolded openings, read alone, give the argument
