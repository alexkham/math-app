## Machinery learned in the complex-numbers batch (beyond the two docs)

1. **States are usually the presets.** These tools have no info-tab system; their states are the "Try these" preset buttons plus reachable special configurations (divide-by-zero, coincident points, r ≠ 1). Wiring pattern used on all ten: additive `explanations` prop, a `stateKey` derived by **exact value-match against the preset values** (e.g. `z1.re === 3 && z1.im === 2 && ...`), special states checked FIRST (`divideByZero`, `coincident`, `radius !== 1`), and the matched entry appended as one extra item inside the tool's existing Key Ideas / Explanation box, rendered with `processContent(...)`. Two keys can be active at once when the tool has two state dimensions (addition-subtraction: display mode + preset pair).
2. **Existing sections often ARE the per-state sections.** These pages were written state-aware ("The Outward Spiral", "Conjugate Pair Division", "Coincident Points"). Map presets onto them, insert the unit as `[content, unitDiv, after]` and author a NEW `after` (a unit never closes a section); create new sections only for uncovered presets. Group sections (preset lists, quadrant lists, degenerate-case lists) get in-text member links (drop bold when a bold term becomes the link).
3. **Diagram modules replicate the component code paths, not just its look**: same W/H/margin/range/scale math, same conditional thresholds (arc visibility, label cutoffs, right-angle markers), same paint order, including off-screen dashed rays (`rayToEdge`) and zoom insets — give per-state unique ids to filters/markers/clipPaths since many SVGs share one page. Copy `fmtNum`/`fmtComplex` from the component so frozen labels match the live tool exactly.
4. **Layout conventions (user-mandated, applied to every complex tool — carry forward):** the tool's container is hardcoded to `width/minWidth/maxWidth: '90%'`; the two-column layout must NEVER wrap (info panel always right of the plane) — grid `minmax(<plane-min>px, 1fr) minmax(320px, 420px)` or flex `nowrap`; the page passes `SiblingsNav maxWidth='100%'` (its default 1380px frame was the main squeeze). Also: inputs must commit live per keystroke (see `CoordInput` in `ComplexPlaneKit.jsx` — focus-guarded sync so typing is never overwritten).
5. **Snapshot fallback:** when tooling blocks `cp`, pre-edit versions of committed-clean files are recoverable via `git show HEAD:<path> > line1-backups/...` at any time — verify the file is clean in git before the first edit and the backup can be materialized later. (The 2026-08-19 session had a persistent permission-classifier outage; backups for the last six complex-numbers tools were pending materialization at handoff time — materialize them from git HEAD before or after committing, using the pre-batch commit as the reference if the batch is already committed.)
6. **Static verification one-liner** (used every pass): scan the page for `id:'<slug>'` in the LIVE `genericSections` (slice from the last `const genericSections=[` — commented heads contain numeric-id duplicates), collect all `](!#slug)` anchors, assert zero orphans/collisions, count `stateUnits.<key>` renders == explanation keys, and grep for forbidden patterns (`↓`, `**[`).
